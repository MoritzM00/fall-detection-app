# Review remediation notes

The September review's five broader changes are implemented in the linked PR. Submitted runs are persisted and recoverable through the recent-runs API and UI. Editing a clip selection does not change a submitted run. Failed runs require an explicit retry, which keeps their source, prepared input, and configuration identity. A worker lease lasts 90 seconds and is renewed every 20 seconds while processing. An expired or legacy ownerless run becomes failed with a retry message. Owner tokens fence completion, failure, and renewal.

Each new run saves sampling, model, prompt, generation, backend kind, and mock fixture version. The worker executes that snapshot. Migrated legacy configurations keep their saved prompt, model, generation, and preprocessing values. Their historical backend kind cannot be established and is recorded as `unknown`; if queued legacy work reaches a worker, it fails clearly rather than silently choosing the current backend. Credentials and endpoint authentication remain runtime settings.

Preparation remains synchronous. At most two distinct requests decode concurrently by default, with a ten-second wait for a slot; identical requests share one in-flight result. Capacity exhaustion returns HTTP 503 with `Retry-After`. This coordinator is process-local, so the supported API deployment is **one API process** (`uvicorn` with one worker). Multiple API workers are outside this coordination contract. Browser navigation or a superseding request suppresses stale UI responses but does not cancel server-side decoding. The upload limit defaults to 512 MiB. The API now enforces request bytes before multipart parsing, with a 64 KiB allowance for multipart overhead, and retains the exact file-byte check while copying to persistent storage. A reverse proxy can apply the same or a stricter request-size limit if one is deployed. Set `FALL_DETECTION_UPLOAD_MAX_BYTES`, `FALL_DETECTION_PREPARATION_SLOTS`, and `FALL_DETECTION_PREPARATION_WAIT_SECONDS` to tune these bounds.

New bundles save verified RGB arrays and JPEG transport frames. Inspection PNGs are optional via `FALL_DETECTION_INSPECTION_PNGS=1`; existing bundles with PNGs remain readable. Retention is opt-in through the dry-run-first command in [retention.md](retention.md). It protects all retained jobs, including failed and retryable jobs, and coordinates with uploads and preparation. No cleanup was run against user data during implementation.

On a disposable generated MPEG-4 clip (40 seconds, 10 fps, 96×64), 16-frame 224-pixel preparations measured 0.027 s for an early window, 0.013 s for a late window, and less than 0.001 s for a late-window cache hit on this machine. These small generated-media figures do not predict real high-resolution performance. The implementation retains exact nearest-PTS selection and full source hashing; no seek or stat-only shortcut was introduced.

A later [representative preparation benchmark](preparation-benchmark.md) measures generated 720p and 1080p clips through 120 seconds, reports phase timings and peak memory, and records the decision to retain full-scan decoding for the measured envelope.

Validation includes backend lifecycle, migration, ownership and preparation tests; four Node tests for extracted frontend state rules; three mounted React hook tests for history recovery, historical selection, and polling failure; and a production frontend build. Full browser interaction testing, live GPU/vLLM compatibility, and model accuracy were not tested. The separate maintenance suggestions in the review (API application factory and development-launcher cleanup) remain deferred.
